#+TITLE: CPNET

* Overview

CPNET은 범주론(Category Theory)에 수학적 기반을 둔 순수 데이터 흐름(Pure Dataflow) 계산 모델임.
본 시스템은 복잡한 시스템의 동작을 예측 가능하고, 테스트 가능하며, 형식적으로 증명할 수 있도록 설계되었음.

핵심 원칙은 다음과 같음.
1.  *모든 상태는 셀(Cell)임*: 시스템의 모든 상태는 명시적인 =Cell= 객체로 표현됨.
2.  *모든 계산은 전파자(Propagator)임*: 셀 간의 관계와 계산은 =Propagator= 네트워크로 정의됨.
3.  *계산과 부수 효과(Side Effect)의 완벽한 분리*: 전파자는 순수한 계산만 수행하며, 상태 변경이나 입출력과 같은 모든 부수 효과는 '효과(Effect)' 객체로 반환됨. 이 효과들은 =runtime= 엔진에 의해 원자적으로 처리됨.

이러한 원칙을 통해, CPNET은 새로운 시스템 언어의 기반이 될 수 있는 매우 순수하고 엄밀한 아키텍처를 갖추었음.

* System Architecture

CPNET은 다음과 같은 명확한 계층 구조의 모듈들로 구성됨.

| 모듈 (Module)     | 역할 (Role)                                                                                                                                               |
|-------------------+-----------------------------------------------------------------------------------------------------------------------------------------------------------|
| =cpnet/core=        | *핵심 도구상자 (Core Toolbox)*: Cell, Effect, Propagator 등 시스템을 구성하는 가장 기본적인 요소를 생성하는 순수 함수들을 제공함.                           |
| =cpnet/category=    | *수학적 기반 (Mathematical Foundation)*: =core=의 요소들이 따르는 범주론의 수학적 구조(객체, 사상, 항등, 합성 등)를 정의함.                                 |
| =cpnet/system=      | *컨테이너 API (Container API)*: 사용자가 생성한 Cell과 Propagator를 담는 =System= 객체를 생성하고 관리하는 주 사용 API를 제공함.                              |
| =cpnet/runtime=     | *실행 엔진 (Execution Engine)*: =System= 객체를 인자로 받아, 네트워크가 안정된 상태(settled state)에 도달할 때까지 전파자를 실행하고 효과를 처리함.           |
| =cpnet/detail=      | *컴포넌트 추상화 (Component Abstraction)*: 여러 셀과 전파자로 구성된 복잡한 컴포넌트를 생성하는 상용구 코드를 추상화하는 =make-component-factory=를 제공함. |
| =cpnet/lib=         | *표준 라이브러리 (Standard Library)*: =apply-gate=와 같이 범용적으로 유용한 컴포넌트들을 제공함.                                                            |
| =cpnet/pure-lambda= | *람다 계산법 구현체 (Lambda Calculus Implementation)*: SKI 콤비네이터를 사용하여 람다 계산법을 구현한 컴포넌트 라이브러리임.                                |

* How to Use CPNET

CPNET으로 계산 네트워크를 구축하는 과정은 다음 단계를 따름.

1.  =make-system= 으로 시스템 컨테이너를 생성함.
2.  =make-cell= 로 시스템의 상태를 표현할 셀들을 정의함.
3.  재사용 가능한 컴포넌트는 별도의 모듈에서 =make-component-factory= 를 사용하여 정의함. 이 팩토리는 인터페이스/내부 셀의 명세와 전파자를 정의하는 함수를 인자로 받음.
4.  정의된 팩토리 함수(=make-*-component=)를 호출하여 시스템에 컴포넌트 인스턴스를 추가함.
5.  *=make-connector-propagator=*, =make-fan-out-propagator= 등과 같은 기본 전파자를 사용하여 컴포넌트의 인터페이스 셀들을 서로 연결함.
6.  *=runtime-settle!=* 함수에 최종적으로 조립된 시스템 객체를 전달하여 실행함.

* Example: The Restaurant System

=examples/restaurant/= 는 CPNET을 사용하여 레스토랑의 판매, 재고, 레시피, 예측 시스템을 통합적으로 시뮬레이션하는 복잡한 예제임.

**시스템 도식화 (System Diagram)**

레스토랑 시스템의 데이터 흐름은 다음과 같이 도식화할 수 있음.

#+BEGIN_SRC ascii-art
                    +------------------+
[ sale-event ] ---> |      Sales       | ---(dishes_sold)--> [ fan-out ] -+
                    +------------------+                                  |
                                                                          |
                    +------------------+      +-------------+             |
[ new-recipe ] ---> |   RecipeBook     | <----+             |             |
                    +------------------+      |             |             |
                           |                  |             |             |
                           (ingredients)      |             |             |
                           |                  |             v             |
                           v                  |      +-------------+      |
                    +------------------+      |      | Forecasting | <----+
                    |    Inventory     |      |      +-------------+
                    +------------------+      |             |
                           |                  |             | (forecast)
                           (low_stock_alert)  |             v
                           |                  |      +-------------+
                           v                  |      |   Display   |
                    +------------------+      |      |  Forecast   |
                    |  Display Alert   | <----+      +-------------+
                    +------------------+
#+END_SRC

1.  *판매 (Sales)*: 외부에서 =sale-event= 가 발생하면, =Sales= 컴포넌트는 판매된 메뉴 목록(=dishes_sold=)을 출력함.
2.  *팬아웃 (Fan-out)*: 판매된 메뉴 목록은 동시에 =RecipeBook= 과 =Forecasting= 컴포넌트로 전달됨.
3.  *레시피 및 재고 (Recipe & Inventory)*: =RecipeBook= 은 메뉴 목록을 받아 필요한 재료(=ingredients=)를 계산하여 =Inventory= 로 전달함. =Inventory= 는 재고를 차감하고, 특정 품목의 재고가 부족할 경우 =low_stock_alert= 를 발생시킴.
4.  *수요 예측 (Forecasting)*: =Forecasting= 은 판매 기록을 바탕으로 가장 많이 팔린 메뉴를 분석하여, 다음 주문에 필요할 재료(=forecast=)를 예측함.
5.  *출력 (Effects)*: 재고 부족 경고와 수요 예측 결과는 최종적으로 'display' 효과를 통해 화면에 출력됨.

* Formal Proof of Rigor

CPNET의 기반은 수학적으로 엄밀한 범주론임.
시스템의 모든 네트워크는 범주론의 공리(Axiom)를 만족해야 함.

1.  *항등 법칙 (Identity Law)*: =f ∘ id = f= and =id ∘ f = f=
2.  *결합 법칙 (Associativity Law)*: =(h ∘ g) ∘ f = h ∘ (g ∘ f)=

=examples/test-category.scm= 파일은 다양한 형태의 네트워크(비어 있는 네트워크, 선형 네트워크, 복잡한 그래프 네트워크 등)를 구성하고, 이들이 실제로 범주론의 공리를 만족하는지 코드를 통해 자동으로 검증함.

#+BEGIN_SRC scheme
;; examples/test-category.scm
...

(assert-judgement "판단 4: 복잡한 그래프 범주는 유효한 범주임." ...)
