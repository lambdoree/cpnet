* 레스토랑 예제: 아키텍처 명세 및 동작 원리

본 문서는 `restaurant` 예제 시스템의 아키텍처, 컴포넌트 명세, 이벤트 기반 데이터 흐름을 설명함.

** 1. 아키텍처 개요

시스템 아키텍처는 **'정적 아키텍처 / 상세 디자인 / 동적 아키텍처'** 3계층 패턴을 따름. 이 패턴은 시스템의 '설계'와 '구현'을 명확히 분리하여 독립성과 재사용성을 극대화함.

- *`static-architecture.scm` (설계도)*: 모든 컴포넌트의 공개 인터페이스(단말 셀)만을 정의함.
- *`detail/*.scm` (구현부)*: 각 컴포넌트의 내부 로직을 독립적으로 구현함.
- *`dynamic-architecture.scm` (배선도 및 조립)*: 구현된 컴포넌트들을 '연결'하여 최종 시스템을 조립함.

** 2. 컴포넌트 명세 및 시스템 배선도

본 다이어그램은 시스템 컴포넌트, 셀, 전파자 관계를 두 부분으로 나누어 도식화함.

- *컴포넌트 연결*: `dynamic-architecture.scm`에 정의된 연결 전파자들의 컴포넌트 공개 단말 셀 연결 방식을 보임.
- *컴포넌트 내부 흐름*: 각 컴포넌트 내부의 데이터 처리 흐름을 보임.

#+begin_src text
;; ==================================================================
;;  I. 컴포넌트 연결 (Inter-Component Wiring)
;;     - Source: `dynamic-architecture.scm`
;;     - `[]`: Component Interface Cell, `()`: Connector Propagator
;; ==================================================================

[main.scm :: sale-event]
       │
       ▼
 [SalesNet :: public-dish-sold]
       │
       ▼
(p-fan-out-sales)
       ├─► [RecipeBookNet :: in-dish-name]
       └─► [ForecastingNet :: in-forecast-dish]


[RecipeBookNet :: out-ingredients] ───(p-recipes->inventory)───► [InventoryNet :: public-ingredients-decrement]


[InventoryNet :: out-low-stock-trigger] ───(p-inventory->alert)───► [CONSOLE ALERT]


[main.scm :: new-recipe-event] ───(p-new-recipe->recipe-book)───► [RecipeBookNet :: in-new-recipe]


;; ==================================================================
;;  II. 컴포넌트 내부 흐름 (Intra-Component Flow)
;;      - Source: `detail/*.scm` files
;;      - `[]`: Internal State Cell, `()`: Internal Propagator
;; ==================================================================

[SalesNet]
  sale-event ──(p-process-sale)──► public-dish-sold


[RecipeBookNet]
  in-new-recipe ──(p-add-recipe)──► [cell-recipes]
  in-dish-name ──(p-recipe-lookup)──┐ (reads [cell-recipes])
                                     ▼
                                  out-ingredients


[ForecastingNet]
  in-forecast-dish ──(p-update-sales-history)──► [cell-sales-history]
                                                          │ (triggers)
                                                          ▼
                                (p-generate-forecast) ◄───┘ (reads [cell-sales-history], [cell-forecast-recipes])
                                         │
                                         ▼
                                      out-ingredient-forecast ──► [CONSOLE FORECAST]


[InventoryNet]
  public-ingredients-decrement ──(p-dispatch-ingredients)──► {event-*}
                                       (reads [cell-event-cell-map])

  {event-*} ──(make-stock-updater)──► {stock-*}, inventory-dirty-flag

  inventory-dirty-flag ──(p-check-all-stock-levels)──► out-low-stock-trigger
                                  (reads [cell-all-stock-info])
                                  (writes {alert-sent-*})
#+end_src

** 3. 이벤트 전파 추론 규칙 (Event Propagation Inference Rules)

본 시스템의 데이터 흐름은 추론 규칙 형식으로 표현 가능함. 각 전파자는 `전제(Premise)`로부터 `결론(Judgement)`을 도출하는 규칙임.

- *컨텍스트 (Γ)*: 시스템 모든 셀의 현재 상태 집합을 나타냄.
- *판단 (Judgement)*: =Γ ⊢ cell := value=는 컨텍스트 Γ 하에서 =cell=이 =value= 값을 가짐을 의미함. =Γ'=는 전파자 실행 후 변경된 컨텍스트임.

*** 이벤트 1: `(sell-dish 'salad 2)` - 판매 이벤트 전파 규칙

**** 1. 초기화 (Initialization)
`main.scm`에서 판매 이벤트 발생, `sale-event` 셀 값 설정됨.
#+begin_src text
Γ₀ ⊢ sale-event := '((item . salad), (quantity . 2))
#+end_src

**** 2. SalesNet: 판매 처리
`p-process-sale` 전파자는 판매 이벤트를 요리 목록으로 변환함.
#+begin_src text
Γ ⊢ sale-event := '((item . i), (quantity . q))
-------------------------------------------------- [p-process-sale]
Γ' ⊢ public-dish-sold := (make-list q i)
#+end_src
/판단: `public-dish-sold`는 `(salad salad)` 값을 가짐./

**** 3. Dynamic Architecture: 이벤트 분배 (Fan-out)
`p-fan-out-sales` 전파자는 판매된 요리 목록을 `RecipeBookNet`과 `ForecastingNet`으로 동시 전달함.
#+begin_src text
Γ ⊢ public-dish-sold := dishes
-------------------------------------------------- [p-fan-out-sales]
Γ' ⊢ in-dish-name := dishes  ∧  in-forecast-dish := dishes
#+end_src

**** 4. RecipeBookNet & ForecastingNet: 병렬 처리

- =RecipeBookNet=: `p-recipe-lookup`은 요리 목록을 재료 목록으로 변환함.
  #+begin_src text
  Γ ⊢ in-dish-name := dishes  ∧  cell-recipes := R
  -------------------------------------------------- [p-recipe-lookup]
  Γ' ⊢ out-ingredients := lookup-ingredients(dishes, R)
  #+end_src
  /판단: `out-ingredients`는 `((lettuce 1)(tomato 1)(lettuce 1)(tomato 1))` 값을 가짐./

- =ForecastingNet=: 판매 기록을 업데이트하고(`p-update-sales-history`), 이를 기반으로 예측을 생성함(`p-generate-forecast`).
  #+begin_src text
  Γ ⊢ in-forecast-dish := dishes  ∧  cell-sales-history := H
  -------------------------------------------------- [p-update-sales-history]
  Γ' ⊢ cell-sales-history := H' (dishes가 추가된 새로운 기록)

  Γ' ⊢ cell-sales-history := H'
  -------------------------------------------------- [p-generate-forecast]
  Γ'' ⊢ out-ingredient-forecast := generate-forecast(H')
  #+end_src

**** 5. Dynamic Architecture: 재료 요청 연결
`p-recipes->inventory` 전파자는 `RecipeBookNet`의 출력을 `InventoryNet`의 입력으로 연결함.
#+begin_src text
Γ ⊢ out-ingredients := ingredients
-------------------------------------------------- [p-recipes->inventory]
Γ' ⊢ public-ingredients-decrement := ingredients
#+end_src

**** 6. InventoryNet: 재고 차감 및 확인
`InventoryNet`은 여러 내부 전파자를 통해 재고를 처리함.
#+begin_src text
Γ ⊢ public-ingredients-decrement := ingredients
-------------------------------------------------- [p-dispatch-ingredients]
Γ' ⊢ event-lettuce := 2  ∧  event-tomato := 2

Γ ⊢ event-lettuce := 2  ∧  stock-lettuce := 50
-------------------------------------------------- [update-lettuce-stock]
Γ' ⊢ stock-lettuce := 48  ∧  inventory-dirty-flag := #t

... (다른 재료에 대해 유사 규칙 적용)

Γ ⊢ inventory-dirty-flag := #t  ∧  cell-all-stock-info := S
-------------------------------------------------- [p-check-all-stock-levels]
Γ' ⊢ out-low-stock-trigger := check-low-stock(S)
#+end_src

**** 7. Dynamic Architecture: 알림 처리
`p-inventory->alert` 전파자는 재고 부족 신호를 받아 콘솔에 경고를 표시함.
#+begin_src text
Γ ⊢ out-low-stock-trigger := low-stock-list
-------------------------------------------------- [p-inventory->alert]
Γ' ⊢ (side-effect: display-alert(low-stock-list))
#+end_src

*** 이벤트 2: `(add-recipe 'pizza ...)` - 상태 업데이트 규칙

**** 1. 초기화 (Initialization)
`main.scm`에서 새 레시피 추가 이벤트 발생.
#+begin_src text
Γ₀ ⊢ new-recipe-event := '(pizza (dough 1) (cheese 1) (sauce 1))
#+end_src

**** 2. Dynamic Architecture: 레시피 전달
`p-new-recipe->recipe-book` 전파자는 이벤트를 `RecipeBookNet`으로 전달함.
#+begin_src text
Γ ⊢ new-recipe-event := recipe-data
-------------------------------------------------- [p-new-recipe->recipe-book]
Γ' ⊢ in-new-recipe := recipe-data
#+end_src

**** 3. RecipeBookNet: 상태 업데이트
`p-add-recipe` 전파자는 `cell-recipes` 내부 상태를 업데이트함.
#+begin_src text
Γ ⊢ in-new-recipe := recipe-data  ∧  cell-recipes := R
-------------------------------------------------- [p-add-recipe]
Γ' ⊢ cell-recipes := (cons recipe-data R)
#+end_src
